專為 Raspberry Pi Pico 2 W (RP2350 + CYW43439) 打造之現代物聯網雙核心課程：
MQTT 物聯網雲端雙向通訊 (MQTTGO.io) ✕ 台灣政府資料開放平臺 (data.gov.tw) API 智慧聯網。

💡 零外接硬體門檻 & 單檔即跑設計 (All-in-One Standalone)：
全套實驗完全不需要外接麵包板、跳線或額外感測器模組！直接善用 Pico 2 W 內建之 CYW43439 2.4GHz Wi-Fi、板載 LED ("LED") 以及 RP2350 內部溫度感測器 (ADC 4) 即可完整運行。所有實驗檔案頂部均已整合 Wi-Fi 設定，填入帳密一鍵執行！

⚙️ RP2350 第二代微控制器優勢

  • 雙架構核心：支援高達 150MHz 運算頻率。
  • 520 KB 內部 SRAM：初代 Pico (264KB) 容量的 2 倍，輕鬆吃下 HTTPS 握手與 JSON 解析緩衝。
  • 4MB 外接 Flash：充足空間存放 MicroPython 固件與 Python 腳本。

📶 CYW43439 無線網路與硬體

  • 2.4GHz Wi-Fi 4 (802.11n)：整合板載高效能天線。
  • 唯一硬體識別碼：machine.unique_id() 動態產出專屬 Client ID，多人同時連線不衝突。
  • 板載 LED 指示燈：作為雲端指令回饋與政府天氣警報燈號。

【理論篇】MQTT 協議原理與核心架構深度解析

在深入動手實作前，徹底理解為什麼 MQTT (Message Queuing Telemetry Transport) 會成為全世界物聯網、智慧家庭與工業 4.0 的事實標準協議。

🔌 1. 為什麼物聯網不直接使用傳統 HTTP？

在傳統網頁開發中，HTTP (超文本傳輸協定) 佔據統治地位。然而對於以微控制器（如 RP2350）、電池供電或依賴行動網路的物聯網裝置來說，HTTP 存在致命的硬體與架構缺陷：

比較維度 傳統 HTTP / REST 協定 物聯網標準 MQTT 協定 物聯網實務影響
通訊架構 Request / Response (請求 - 回應) Publish / Subscribe (發布 - 訂閱) MQTT 實現伺服器端主動即時推播，無需設備反覆發送請求輪詢。
封包報頭開銷 數百 Bytes 至數 KB (Header、Cookies) 最小僅需 2 Bytes 固定報頭 極大節省 2.4GHz Wi-Fi 封包傳輸量，功耗減少 80% 以上。
連線機制 每次傳輸均需重建 TCP 三向交握 單一 TCP 長連線 (Persistent Connection) 大幅降低連線延遲，在不穩定或弱網環境下仍能極速收發。
裝置穿透 (NAT) 被動接收需設定 Port Forwarding 或公網 IP 雙方均向中間 Broker 建立對外連線 位於家用 Wi-Fi 或內網的 Pico 2 W 無需任何防火牆設定即可雙向通訊。

📡 2. Pub/Sub (發布 / 訂閱) 模型與三重解耦架構

MQTT 的靈魂在於發布者 (Publisher) 與訂閱者 (Subscriber) 之間完全互不相識，所有的訊息中繼與路由全部交由訊息代理人 (Broker) 統一調度：

➔ 發布溫度 ➔
☁️
MQTTGO Broker
mqttgo.io:1883
➔ 即時推播 ➔
📱
手機 / 電腦瀏覽器
Subscriber (訂閱端)
空間解耦 (Space Decoupling)

雙方都不需要知道彼此的 IP 位址或實體位置，只需連接至同一個 Broker 即可收發。

時間解耦 (Time Decoupling)

發布訊息時，訂閱者即使離線，也可透過保留訊息 (Retain) 或離線緩衝在重新上線時立即接收。

同步解耦 (Synchronization Decoupling)

Pico 2 W 發布數據後立刻繼續執行本機程式碼，完全不會被遠端網路延遲卡死 (Non-blocking)。

🏷️ 3. 主題 (Topic) 階層設計與萬用字元運算

MQTT 透過類似檔案路徑的斜線 (/) 階層進行訊息路由。例如：pico2w/e6614103e72c8328/temp。

  • 單層萬用字元 +：匹配路徑中的單一階層。
    例如訂閱 pico2w/+/temp，可以同時收到全班所有同學 Pico 發布的溫度數據！
  • 多層萬用字元 #：必須放在主題末端，匹配該層以下的所有子路徑。
    例如訂閱 pico2w/#，即可監聽 pico2w/ 下包含 temp、led 等全體訊息廣播。
  • 命名黃金原則：切勿以斜線 / 開頭（會多產生一個空層級浪費頻寬）；建議一律使用小寫字母；最前綴使用硬體唯一 ID 避免名稱衝突。

🛡️ 4. QoS (Quality of Service) 服務品質三大等級

等級 名稱 通訊機制 資源消耗 最佳應用情境
QoS 0 At most once (最多送一次) 發送端送出即忘 (Fire and Forget)，無確認回執 極低，零額外封包 週期性感測數據（如每 5 秒回傳一次溫度，偶爾遺失一筆無關緊要）。
QoS 1 At least once (至少送達一次) 發送端等待 PUBACK 回應，逾時重傳（可能重複） 中等，需記錄訊息狀態 開關或控制指令（如遠端切換 LED、開門指令，務求必達）。
QoS 2 Exactly once (恰好送達一次) 四階段握手確認 (PUBREC, PUBREL, PUBCOMP) 最高，佔用記憶體與頻寬 電子支付、金融計費、重大工業連鎖安全開關。微控制器通常不建議使用。

⚙️ 5. 關鍵進階機制：Retain、心跳與遺囑

  • Retain (保留訊息)：Broker 會長久保存該主題最後發布的一筆有效數值。當新的手機或監控儀表板剛連上線時，無需等待下一次發布即可立即取得最新設備狀態。
  • Keepalive (心跳保活)：客戶端定時發送 PINGREQ，Broker 回應 PINGRESP，防止家用 NAT 路由器逾時關閉連線。
  • LWT (Last Will and Testament 遺囑)：客戶端連線時在 Broker 預存遺囑訊息。若 Pico 意外斷電或斷網，Broker 會主動向全體發布「設備已離線」通報！

🇹🇼 6. 認識台灣 MQTTGO.io 開源平台

  • 在地化超低延遲：由台灣尤濬哲老師維護，伺服器部署在台灣在地節點，國內網路 ping 延遲通常小於 20ms。
  • 零門檻免註冊：完全不需要申請 API Key 或個人帳號密碼，開箱即連。
  • 雙軌連接埠支援：
    • TCP 1883：微控制器（Pico 2 W）標準 Socket 直連。
    • WebSocket 8000：電腦與手機瀏覽器免安裝任何軟體直接收發。

# lab1_mqttgo_iot.py - 實驗 1：MQTT 物聯網雙向雲端通訊 (MQTTGO.io 台灣在地 Broker)
# 適用硬體：Raspberry Pi Pico 2 W (RP2350 + CYW43439)
# 零外接零件：使用 RP2350 內部溫度感測器 (ADC 4) 與板載 LED ("LED")

import time
import network
import machine
from machine import Pin, ADC
import ubinascii
from umqtt.simple import MQTTClient

# ==========================================
# 1. Wi-Fi 連線設定 (單檔即跑，直接在此填寫)
# ==========================================
WIFI_SSID = "YOUR_WIFI_SSID"          # 請替換為您的 2.4GHz Wi-Fi 名稱
WIFI_PASSWORD = "YOUR_WIFI_PASSWORD"  # 請替換為您的 Wi-Fi 密碼

# ==========================================
# 2. 硬體引腳與感測器初始化
# ==========================================
led = Pin("LED", Pin.OUT)
temp_sensor = ADC(4)  # RP2350 內部溫度感測器通道

# ==========================================
# 3. MQTT 伺服器與主題設定 (MQTTGO.io)
# ==========================================
# 依據 Pico 2 W 硬體唯一 ID 產生唯一 Client ID 與專屬主題，保證不與他人衝突
DEVICE_ID = ubinascii.hexlify(machine.unique_id()).decode('utf-8')
MQTT_BROKER = "mqttgo.io"  # 台灣在地開源免費 MQTT Broker
MQTT_PORT = 1883           # 標準 MQTT TCP 連接埠

TOPIC_PUB_TEMP = f"pico2w/{DEVICE_ID}/temp"  # Pico 定期發布溫度的主題
TOPIC_SUB_LED  = f"pico2w/{DEVICE_ID}/led"   # Pico 訂閱接收控制指令的主題

def read_temperature():
    """讀取 RP2350 內部溫度感測器 (攝氏 °C)"""
    conversion_factor = 3.3 / 65535
    reading = temp_sensor.read_u16() * conversion_factor
    # RP2350 內部溫度計算公式：27 - (Vbe - 0.706) / 0.001721
    return 27 - (reading - 0.706) / 0.001721

def connect_wifi():
    """連線至 Wi-Fi 基地台"""
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    if not wlan.isconnected():
        print(f"正在連線至 Wi-Fi: {WIFI_SSID} ...")
        wlan.connect(WIFI_SSID, WIFI_PASSWORD)
        timeout = 20
        while not wlan.isconnected() and timeout > 0:
            time.sleep(0.5)
            timeout -= 1
            print(".", end="")
    if wlan.isconnected():
        ip = wlan.ifconfig()[0]
        print(f"\n[成功] Wi-Fi 已連線！本機 IP: {ip}")
        return True
    else:
        print("\n[錯誤] Wi-Fi 連線逾時，請檢查 SSID 與密碼！")
        return False

def on_message_received(topic, msg):
    """當 MQTT Broker 下發訊息至訂閱主題時觸發的回呼函式"""
    topic_str = topic.decode("utf-8")
    msg_str = msg.decode("utf-8").strip().lower()
    print(f"\n📩 [MQTT 收到指令] 主題: {topic_str} | 內容: {msg_str}")
    
    if msg_str in ("on", "1", "true"):
        led.on()
        print("💡 板載 LED 已開啟 (ON)")
    elif msg_str in ("off", "0", "false"):
        led.off()
        print("💤 板載 LED 已關閉 (OFF)")
    elif msg_str == "toggle":
        led.toggle()
        print("🔄 板載 LED 狀態已切換")
    else:
        print(f"❓ 未知指令: {msg_str} (支援指令: on, off, toggle)")

def main():
    print("=" * 65)
    print("🚀 實驗 1：Pico 2 W - MQTT 雙向雲端通訊 (MQTTGO.io)")
    print("=" * 65)
    
    if not connect_wifi():
        return
        
    client_id = f"pico2w_{DEVICE_ID}"
    print(f"\n正在連線至 MQTT Broker: {MQTT_BROKER}:{MQTT_PORT} ...")
    print(f"裝置專屬 Client ID: {client_id}")
    
    # 建立 MQTT 客戶端
    client = MQTTClient(client_id, MQTT_BROKER, port=MQTT_PORT, keepalive=60)
    client.set_callback(on_message_received)
    
    try:
        client.connect()
        print("✅ MQTT Broker 連線成功！")
        
        # 訂閱控制主題
        client.subscribe(TOPIC_SUB_LED)
        print(f"📡 已訂閱控制主題: {TOPIC_SUB_LED}")
        
        # 輸出網頁操作指引
        print("\n" + "*" * 65)
        print("🌐 【MQTTGO.io 雲端雙向測試指南】")
        print("👉 請在電腦或手機瀏覽器開啟： https://mqttgo.io/")
        print("1. 接收溫度數據：")
        print(f"   在「訂閱主題」欄位貼上： {TOPIC_PUB_TEMP}")
        print("   點擊「訂閱」，每 5 秒即可看見 Pico 回傳之即時溫度！")
        print("2. 遠端控制 LED 燈：")
        print(f"   在「發布主題」欄位貼上： {TOPIC_SUB_LED}")
        print("   在「發布訊息」填入： on 、 off 或 toggle，點擊「發布」！")
        print("*" * 65 + "\n")
        
        last_pub_time = 0
        while True:
            # 非阻塞檢查是否有來自雲端的訂閱訊息
            client.check_msg()
            
            # 每 5 秒發布一次當前板載溫度
            now = time.time()
            if now - last_pub_time >= 5:
                temp = read_temperature()
                temp_msg = f"{temp:.2f}"
                client.publish(TOPIC_PUB_TEMP, temp_msg)
                print(f"📤 [MQTT 發布] 溫度: {temp_msg} °C -> 主題: {TOPIC_PUB_TEMP}")
                last_pub_time = now
                
            time.sleep(0.1)
            
    except KeyboardInterrupt:
        print("\n使用者中斷程式執行。")
    except Exception as e:
        print(f"\n❌ MQTT 運行異常: {e}")
    finally:
        try:
            client.disconnect()
            print("MQTT 連線已關閉。")
        except:
            pass

if __name__ == "__main__":
    main()

【理論篇】台灣政府開放資料 (data.gov.tw) 與 RESTful API 深度解析

了解什麼是國家級開放資料、RESTful 架構模式、JSON 階層資料解析，以及微控制器在記憶體受限環境下的 5 大硬核設計原則。

🏛️ 1. 什麼是政府開放資料 (Open Government Data)?

政府開放資料是指由各級政府機關在職權範圍內取得或產生的各類公共資料，在兼顧個人隱私與國家安全的前提下，以開放格式 (Open Format)、機器可讀 (Machine-Readable) 且免收授權費的方式向大眾釋出。

台灣平臺：data.gov.tw

由數位發展部 (moda) 與國發會建置維護，整合中央與地方超過 5 萬種資料集，包含氣象、環境、水利、交通、防災等。

API 服務資料集 (rtt=1737)

在平臺搜尋篩選代碼 rtt=1737 代表具備即時線上 API 查詢端點，提供程式自動連線讀取 JSON 回應，而非人工下載靜態 CSV/PDF 檔。

通用授權金鑰機制

政府平臺為推廣教育與研究，內建標準通用授權碼（如 rdec-key-123-45678-011121314），學員免個別註冊即可在專案中公開調用。

🌐 2. RESTful API 核心架構與組成解構

REST (Representational State Transfer) 是現代網際網路服務最通用的軟體架構風格。它將網路上的所有服務視為「資源」，並透過標準的 HTTP 協議進行操作：

HTTP 動詞 語義角色 在開放資料中的應用 特性 (Idempotency)
GET 讀取 / 查詢資源 政府開放資料核心（99.9% 均為 GET）：取得氣溫、雨量、AQI 數值。 安全、冪等（多次呼叫伺服端狀態不改變）、可被快取。
POST 新增 / 建立資源 向伺服器提交新數據（如 IoT 感測回傳、Webhook 通報）。 非冪等，每次呼叫會在伺服器產生新紀錄。
PUT / DELETE 更新 / 刪除資源 修改或移除資源（開放資料通常不對外開放此權限）。 冪等性操作。

• 主機名稱 (Host)：opendata.cwa.gov.tw (中央氣象署主機)
• 端點路徑 (Path)：/api/v1/rest/datastore/O-A0003-001 (觀測資料集資源)
• 查詢參數 (Query String)：授權碼 + 測站代碼過濾條件

🧩 3. JSON (JavaScript Object Notation) 語法與防禦性解析

JSON 是一種輕量級純文字資料交換格式，易於人類閱讀，也極易於電腦解析。在 MicroPython 中，呼叫 response.json() 會自動將其轉化為 Python 的原生型別：

JSON 物件 { "key": "value" }

對應 Python 的 字典 (Dictionary)。透過鍵值對儲存屬性（例如 {"StationName": "臺北"}）。

JSON 陣列 [ "item1", "item2" ]

對應 Python 的 串列 (List)。有序元素清單（例如 records["Station"] 包含測站清單）。

🚨 微控制器必備技能：防禦性取值 (Defensive Access)
在真實世界中，政府氣象測站可能因儀器維修或感測器校正，暫時缺少某個欄位。
• ❌ 危險寫法：temp = data["records"]["Station"][0]["WeatherElement"]["AirTemperature"]
若該欄位缺失，MicroPython 會立刻拋出 KeyError 或 IndexError，導致無人看管的 Pico 2 W 當場崩潰死機！
• ✅ 安全防禦寫法：temp = weather_elem.get("AirTemperature", 0.0)
使用 .get(key, default)，當欄位不存在時安全回傳預設值，保證裝置 365 天穩定運行！

⚡ 4. 微控制器 (MCU) 串接公開 API 的 5 大硬核挑戰

挑戰項目 潛在危害 Pico 2 W 最佳實踐解決方案
1. RAM 記憶體溢位 全台觀測 JSON 高達 650 KB，超出 MCU 堆疊上限，引發 MemoryError 死機。 在 URL 加上 &StationId=466920 伺服端過濾，將回傳大幅縮減至 2 KB（縮小 99.7%）。
2. TLS 握手與堆疊破碎 HTTPS 加密握手需佔用 30~50KB 暫存緩衝，長時間連續連線造成記憶體碎片化 (Fragmentation)。 在每次發送 HTTP 請求前與關閉回應後，主動呼叫 gc.collect() 執行記憶體回收。
3. API 頻率與限制 (Rate Limit) 頻繁發送請求（如每秒一次）會被政府資安防護判定為 DDOS 攻擊而封鎖 IP。 氣象署觀測站約每 10~60 分鐘更新一次，Pico 設備端每 60~300 秒輪詢一次最符合資料新鮮度與禮貌原則。
4. Socket 連線洩漏 (Leak) 忘記關閉回應物件，耗盡 MicroPython 內建的 Socket 上限（通常僅 4~8 個），導致後續連線全部報錯 OSError: 12。 使用 try-finally 結構，確保無論成功或失敗均嚴格執行 response.close()。
5. 虛實整合 (Data-to-Physical) 雲端大數據僅停留在數字層面，失去邊緣運算的價值。 將降雨量、天候字串提取為實體硬體控制：下雨快閃板載 LED 示警，晴天常亮確認，實現智慧生活物聯網！

# lab2_gov_opendata.py - 實驗 2：台灣政府開放資料 (data.gov.tw) API 串接與智慧實體警報
# 適用硬體：Raspberry Pi Pico 2 W (RP2350 + CYW43439)
# 零外接零件：使用板載 LED ("LED") 作為智慧天候燈號警報器
# 資料來源：政府資料開放平臺 (data.gov.tw) / 中央氣象署開放資料 API (資料集 O-A0003-001)

import time
import network
import urequests
import gc
from machine import Pin

# ==========================================
# 1. Wi-Fi 連線設定 (單檔即跑，直接在此填寫)
# ==========================================
WIFI_SSID = "YOUR_WIFI_SSID"          # 請替換為您的 2.4GHz Wi-Fi 名稱
WIFI_PASSWORD = "YOUR_WIFI_PASSWORD"  # 請替換為您的 Wi-Fi 密碼

# ==========================================
# 2. 硬體引腳初始化
# ==========================================
led = Pin("LED", Pin.OUT)

# ==========================================
# 3. 台灣政府資料開放平臺 API 設定
# ==========================================
# 常用氣象測站代碼 (StationId)：
# 466920: 臺北 | 466940: 基隆 | 467490: 臺中 | 467410: 臺南 | 467440: 高雄 | 466990: 花蓮
STATION_ID = "466920"  # 預設：臺北測站
STATION_NAME_DESC = "臺北"

# 政府開放資料平臺標準通用授權金鑰 (免個人註冊即可公開調用)
GOV_AUTH_KEY = "rdec-key-123-45678-011121314"

# 透過 StationId 進行精準過濾，回傳僅約 2KB 輕量 JSON，徹底避免 MicroPython 記憶體溢位 (MemoryError)
API_URL = f"https://opendata.cwa.gov.tw/api/v1/rest/datastore/O-A0003-001?Authorization={GOV_AUTH_KEY}&StationId={STATION_ID}"

def connect_wifi():
    """連線至 Wi-Fi 基地台"""
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    if not wlan.isconnected():
        print(f"正在連線至 Wi-Fi: {WIFI_SSID} ...")
        wlan.connect(WIFI_SSID, WIFI_PASSWORD)
        timeout = 20
        while not wlan.isconnected() and timeout > 0:
            time.sleep(0.5)
            timeout -= 1
            print(".", end="")
    if wlan.isconnected():
        ip = wlan.ifconfig()[0]
        print(f"\n[成功] Wi-Fi 已連線！本機 IP: {ip}")
        return True
    else:
        print("\n[錯誤] Wi-Fi 連線逾時，請檢查 SSID 與密碼！")
        return False

def flash_led(times=3, delay=0.15):
    """LED 告警快閃 (下雨或惡劣天候提示)"""
    for _ in range(times):
        led.on()
        time.sleep(delay)
        led.off()
        time.sleep(delay)

def fetch_taiwan_opendata():
    """向政府開放資料 API 發送 HTTP GET 請求並解析即時天氣"""
    gc.collect()  # 請求前主動回收記憶體
    print(f"\n🌐 發送 HTTPS GET 至政府開放資料平臺...")
    print(f"🔗 測站代號: {STATION_ID} ({STATION_NAME_DESC})")
    
    response = None
    try:
        headers = {"User-Agent": "Pico2W-OpenDataClient/1.0"}
        response = urequests.get(API_URL, headers=headers)
        
        if response.status_code == 200:
            print("✅ 成功取得 API 回應 (HTTP 200 OK)！解析 JSON 中...")
            data = response.json()
            
            # 解析 CWA Datastore 結構
            records = data.get("records", {}).get("Station", [])
            if not records:
                print("⚠️ 未找到該測站資料，請確認測站代碼。")
                return
                
            station = records[0]
            station_name = station.get("StationName", STATION_NAME_DESC)
            obs_time = station.get("ObsTime", {}).get("DateTime", "未知")
            
            weather_elem = station.get("WeatherElement", {})
            weather_desc = weather_elem.get("Weather", "未知")
            temp = float(weather_elem.get("AirTemperature", 0.0))
            humidity = weather_elem.get("RelativeHumidity", "未知")
            
            # 取得即時降雨量
            precip = 0.0
            now_elem = weather_elem.get("Now", {})
            if isinstance(now_elem, dict) and "Precipitation" in now_elem:
                try:
                    precip = float(now_elem.get("Precipitation", 0.0))
                except:
                    precip = 0.0
                    
            # 顯示解析後的即時開放資料
            print("-" * 50)
            print(f"🏛️ 【政府開放資料即時天氣觀測】")
            print(f"📍 觀測地點：{station_name} (測站: {STATION_ID})")
            print(f"🕒 觀測時間：{obs_time}")
            print(f"🌤️ 天氣狀況：{weather_desc}")
            print(f"🌡️ 目前氣溫：{temp:.1f} °C")
            print(f"💧 相對濕度：{humidity} %")
            print(f"🌧️ 累積降雨：{precip} mm")
            print("-" * 50)
            
            # ==========================================
            # 4. 硬體實體連動邏輯 (智慧燈號提示)
            # ==========================================
            is_raining = ("雨" in weather_desc) or (precip > 0.0)
            
            if is_raining:
                print("🚨 [天候警報] 偵測到目前有降雨！出門請攜帶雨具 ☔")
                print("💡 板載 LED 連續快閃警示...")
                flash_led(times=6, delay=0.1)
            else:
                print("✨ [天候良好] 目前無雨，天氣舒適！")
                # 天氣良好時，LED 恆亮 1.5 秒表示正常運行
                led.on()
                time.sleep(1.5)
                led.off()
                
        else:
            print(f"❌ API 請求失敗，狀態碼: {response.status_code}")
            
    except Exception as e:
        print(f"❌ 擷取開放資料時發生錯誤: {e}")
    finally:
        if response:
            response.close()
        gc.collect()

def main():
    print("=" * 65)
    print("🚀 實驗 2：Pico 2 W - 台灣政府開放資料 (data.gov.tw) API 串接")
    print("=" * 65)
    
    if not connect_wifi():
        return
        
    print("\n系統初始化完成，將每 60 秒自動向政府開放資料平臺更新一次天候資料...")
    fetch_taiwan_opendata()
    
    while True:
        try:
            for i in range(60, 0, -10):
                time.sleep(10)
                print(f"⏳ 距離下次政府資料更新尚餘: {i-10} 秒...")
            fetch_taiwan_opendata()
        except KeyboardInterrupt:
            print("\n使用者停止程式執行。")
            led.off()
            break

if __name__ == "__main__":
    main()

實務除錯、踩坑經驗與 FAQ

1

Wi-Fi 一直連不上？（檢查 2.4GHz 頻段）

CYW43439 晶片僅支援 2.4GHz Wi-Fi，不支援 5GHz。若使用手機熱點，請務必開啟「最大相容性」或強制設定頻段為 2.4GHz。

2

校園 Wi-Fi 彈出網頁認證（Captive Portal）？

學校或企業常見需登入帳密的 802.1X / 網頁認證，Pico 2 W 無法直接處理網頁點擊認證。實體教學現場建議以手機熱點或便攜 4G 分享器進行連線。

3

發布 MQTT 訊息後，程式好像卡住了？

請確認迴圈內呼叫的是 client.check_msg()（非阻塞檢查），切勿誤用阻塞式 wait_msg()，否則會一直等到雲端有新訊息才往下走。

4

抓取政府開放資料噴出 MemoryError？

務必確認 URL 尾端有帶上 &StationId=466920 參數。若無此參數，伺服器會一口氣回傳全台灣 360+ 個測站（650KB），瞬間超出 MicroPython 堆疊記憶體！

5

在瀏覽器輸入 Pico 的 IP (如 192.168.x.x) 顯示「拒絕連線 (ERR_CONNECTION_REFUSED)」？

原因：Pico 2 W 在這兩個實驗中扮演的是 MQTT 客戶端 (Client) 或 API 客戶端，負責向外連線至雲端伺服器，板子內部並沒有啟動本機 HTTP Web Server (Port 80)！因此直接開啟 Pico 的 IP 會被拒絕連線。
正確操作方式：
• 實驗 1 (MQTT)：請在電腦或手機瀏覽器開啟 https://mqttgo.io/ 雲端測試台，透過該網頁訂閱主題或發布指令。
• 實驗 2 (政府開放資料)：資料會自動定期抓取並在 Thonny 終端機印出，並連動板載 LED 燈號，無需打開瀏覽器。
